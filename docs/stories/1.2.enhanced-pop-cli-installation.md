# Story 1.2: Pop-CLI Installation System

## Status

Approved

## Story

**As a** Kit-Dot user,  
**I want** a reliable Pop-CLI installation system that leverages existing platform detection to install blockchain node management tools,  
**so that** I can launch blockchain nodes with minimal setup regardless of whether Rust is pre-installed on my system.

## Acceptance Criteria

1. Pop-CLI installer must leverage existing platform detection from Story 1.1 (Linux/macOS/Windows/WSL)
2. Installer must implement multiple fallback strategies: pre-compiled binaries → cargo install → source compilation
3. Installation must utilize existing Rust installation from Story 1.1 when available
4. Installation failures must be handled gracefully with clear error messages and recovery guidance
5. Tool PATH management must configure `~/.kit-dot/tools` directory correctly
6. PopCliManager must provide interface for executing pop-cli commands with chain features

## Implementation Tasks

- [ ] **Create PopCliInstaller with platform detection integration**

  - Import platform utilities from Story 1.1
  - Implement multi-strategy installation (binaries → cargo → source)
  - Use chain-only features: `--no-default-features --features chain`

- [ ] **Configure tool PATH management**

  - Install to `~/.kit-dot/tools` directory
  - Update PATH for current session
  - Verify installation with `pop --version`

- [ ] **Create PopCliManager interface**
  - Provide `checkInstallation()` and `execute()` methods
  - Support `--skip-confirm` for automated chain launching

## Dev Notes

### **DEPENDENCY: Story 1.1 Must Be Complete**

This story builds directly on Story 1.1: Platform Detection & Rust Installation. Story 1.1 must be marked as "Done" before this story can be implemented.

### Story 1.1 Integration Points

- **Platform Detection**: Use existing `PlatformDetector` class and `isRustInstalled()` utility
- **Rust Toolchain**: Leverage existing Rust installation when available
- **User Consent**: Tool installation consent already established in init flow

### Pop-CLI Installation Strategy

Implement multi-strategy installation hierarchy per `docs/pop-cli-integration-plan.md#installation-strategies`:

1. **Pre-compiled binaries** (fastest, no Rust needed)
2. **Cargo install** with chain features: `--no-default-features --features chain`
3. **Source compilation** (fallback)
4. **Manual instructions** (if automated methods fail)

### Technical Constraints

- Install to `~/.kit-dot/tools` directory
- Use chain-only features for ~50% size reduction
- Handle PATH updates for current session
- Support `--skip-confirm` flag for automated chain launching

### File Locations

**New files to create:**

- `src/tools/pop-cli/installer.ts` - PopCliInstaller with multi-strategy installation
- `src/tools/pop-cli/manager.ts` - PopCliManager for command execution
- `src/tools/pop-cli/__tests__/installer.test.ts` - Installation tests

**Import from Story 1.1:**

- `src/tools/platform-detector.ts` - Platform detection utilities
- Existing Rust installation utilities and consent mechanisms

### Testing Requirements

- Unit tests for installation strategies (binary, cargo, source)
- Mock GitHub API and platform detection calls
- Error handling verification for installation fallbacks
- PATH management and PopCliManager integration tests
